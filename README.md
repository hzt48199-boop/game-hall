# cbox · 慈善盒子 (Charity Box)

> **Open Charity Box. Open a world of compassion.** / 打开慈善盒子,开启一个充满爱心的世界。

**cbox** is the name of this game hall. The brand and tagline are shown in the lobby and on every game screen. The UI is **English by default**; the lobby has a visible **「中文」** button that switches the whole UI (lobby + all games) to Chinese (and back with **English**). The choice is remembered (`localStorage` key `gh_lang`; WeChat storage in the mini-game).

## Phase 4 (this release)

- **New games, ranked at the top of the lobby:** **Texas Hold'em** (2–6 players, virtual chips only) and **International Chess**.
- Friend rooms, join-by-code, quick match, vs-computer (Easy/Normal/Hard) and all existing sound effects work for every game exactly as before; both new games have the same sound / music toggles on every screen.
- **i18n:** every drawn string, button label, toast and engine message goes through one dictionary: `client/i18n.js` (`t()` + pattern rules for dynamic strings). English source strings are the keys; Chinese is the dictionary value. Add a language by adding a dictionary.

### International Chess (`shared/chess.js`, `shared/ai-chess.js`)
- Full rules: castling (all conditions), en passant, promotion with piece choice (picker in the UI), check / checkmate / stalemate, draws by threefold repetition, fifty-move rule, insufficient material. Server-validated (same engine) in friend rooms and quick match; resign supported; reconnect works like the other 2-player games.
- Move generation is verified by **perft** on the six standard test positions (start position depth 5 = 4,865,609 nodes, Kiwipete, and positions 3–6).
- AI: negamax / alpha-beta, iterative deepening, quiescence search, transposition table (Zobrist), MVV-LVA + killer + history ordering, piece-square evaluation, repetition awareness. Easy ≈ shallow + random among decent moves, Normal = depth 3, Hard = iterative deepening within a time limit (≈ 2 s).
- UI: tap a piece to see legal moves (dots / capture rings), last-move and check highlights, coordinates, the board flips for Black, SAN of the last move.

### Texas Hold'em (`shared/holdem.js`, `shared/ai-holdem.js`)
- **Virtual chips only — for entertainment only, no cash value, not redeemable.** Same compliance posture as Zha Jin Hua (no recharge / withdrawal / exchange anywhere). Each player starts every session with 1000 chips; blinds 10/20; busted players re-buy (virtual).
- 2–6 players (host chooses the table size in a friend room; empty seats are filled by the computer). Dealer button rotates, heads-up blind rules, pre-flop / flop / turn / river, min-raise rules (short all-ins do not reopen the betting), all-ins with **side pots**, split pots, showdown reveals only players still in the hand. Hole cards of others are never sent to a client (server `view()`).
- Hand evaluator ranks best-5-of-7 (wheel straight, two trips → full house, kickers…).
- AI: Monte-Carlo equity against random hands compared with pot odds. Easy = loose and noisy; Normal = solid; Hard = value-bet sizing, occasional bluffs and stack-aware shoves.
- New sounds (generated by `tools/genaudio.js`, appended so the older audio stays byte-identical): `chessmove`, `chesscap`, `chesscheck`, `knock` (check), `allin`, `flip` (community card), `potwin`; `chips` / `fold` / `deal` reuse the existing files.

## Watch ad, get chips (看广告领筹码)
Lobby button **Watch ad · +500 chips** (Chinese: 看广告领筹码 +500) adds 500 *virtual* Happy Beans/chips to the player's local balance. Entertainment only: no cash value, not redeemable.
- Flow: tap -> server `adStart` -> one-time ticket (`adTicket`) -> full-screen ad (`client/ads.js` provider) -> `adClaim` -> `adGrant` (+500). Errors come back as `adDenied` with a code (`cap`, `cooldown`, `badticket`, `expired`, `toosoon`), shown via i18n.
- Server rules (`server/ads.js`, tested in `tests/ads.test.js`): ticket single-use and tied to the player token, >= 5 s between start and claim, ticket expires after 10 min, 60 s cooldown between claims, 5 claims per UTC day per player, plus a looser 20/day cap per IP against token farming. Balances live in the client's localStorage (`gh_beans`) as before, so limits are enforced by session token + IP and cannot be perfectly tamper-proof; the chips have no value anyway.
- Tunables: `Ads.create({amount, minMs, cooldownMs, dailyCap, ipDailyCap, ttlMs})` in `server/server.js`.

### Plugging in a real ad network
1. Implement a provider in `client/ads.js` (or a new file loaded before `app.js`): `GH.Ads.register({ name: 'adsense', placeholder: false, show: function (ctx) { return new Promise(function (resolve) { /* show the rewarded ad; resolve(true) ONLY when the reward is granted (e.g. AdSense H5 `adBreak` type 'reward' -> `adViewed`; AdMob rewarded `onUserEarnedReward`; WeChat `wx.createRewardedVideoAd(...).show()` -> `onClose(res.isEnded)`), resolve(false) on skip/no-fill/error */ }); } })`.
2. Set `adProvider: 'adsense'` in `web/js/config.js` (`self.GH_CONFIG`) - or call `GH.Ads.use('adsense')`. `placeholder: false` makes the real network draw its own UI; the app only shows its placeholder panel for the `placeholder` provider.
3. Add the network's script tag to `web/index.html` (AdSense needs an approved site + `ads.txt`; WeChat needs a traffic-owner account and the ad unit id). Block gambling/adult/investment categories in the network console.
4. Nothing changes on the server: ticket, timing, cooldown and cap checks stay as they are.

## 运行

需要 Node.js 18+(本次在 Node 20 上测试)。

```bash
cd server && npm install && cd ..    # 仅服务器需要 ws 依赖
node server/server.js                # 联机服务器,默认 ws://localhost:8081  (PORT=xxxx 改端口)
node web/serve.js 8080               # 网页静态服务,浏览器打开 http://localhost:8080
```

- 网页默认连接 `ws://<当前主机名>:8081`;HTTPS 页面则连 `wss://<当前主机>/ws`(需自行用 nginx 等反代)。
  也可临时用 `http://localhost:8080/?server=ws://host:port` 指定,或修改 `web/js/config.js`。
- **人机对战不需要服务器**,只开 `web/serve.js` 即可。联机(好友房 / 匹配)需要联机服务器。
- 服务器环境变量: `PORT`(默认 8081)、`GRACE_MS`(断线保留时间,默认 60000 毫秒)、`TURN_MS`(真人回合超时转托管,默认 45000)、`BOT_DELAY`(电脑出手停顿,默认 700 毫秒)。

## 规则与实现要点

- **五子棋**:15×15,黑先,自由规则——五连及以上(含长连)即胜,无禁手;满盘和棋。AI:启发式威胁评分(简单/普通),困难档为 α-β 深度 3 的 minimax + 全盘棋形评估。
- **中国象棋**:完整走法(蹩马腿、塞象眼、炮架、兵过河、九宫)、将军 / 应将、将死、困毙判负、飞将(将帅照面)、120 步无吃子和棋。AI:α-β,简单深度 1(带随机),普通深度 2,困难深度 3。
- **军棋**:5×12 棋盘、25 子/方;铁路(非工兵直线、工兵可拐弯)、行营(可斜走且不可被攻击)、大本营(入内不能再动)、河中三座桥、地雷(仅工兵可挖,其他攻击者被炸)、炸弹(碰谁都同归于尽)、同级同归、夺旗获胜、无子可动判负;**暗棋**——服务器只发送己方真实棋子,对方棋子显示为「?」,战斗只公开阵亡一方。布阵可随机或点两子互换,服务端校验(军旗在大本营、地雷在后两排、炸弹不在第一排)。AI 只使用己方视角(不偷看),按对方剩余棋子概率估算吃子期望。
- **联机服务器**(`server/server.js`):房间号 6 位数字;所有走法在服务端用共享规则引擎校验(轮次、合法性),非法走法返回错误并重发快照;会话 token 存本地,断线 60 秒内用 token 重连自动恢复房间与棋局,超时判对方获胜;对方断线时界面提示;简单的限流与消息大小限制。
- **音频**(全部由 `tools/genaudio.js` 程序合成,**原创、无任何第三方/版权素材**,可重新生成):
  - 音效:`click`(按钮)、`place`(落子)、`capture`(吃子/对战)、`wait`(等待对手的循环节拍,用于房间等待 / 匹配 / 对方断线 / 军棋等对方布阵)、`start`(开局)、`end`(终局)、`win`(胜利)、`lose`(失败)。
  - 背景音乐:`music_chinese`(D 宫五声音阶,拨弦古筝质感 + 轻木鱼,用于象棋 / 军棋)、`music_calm`(C 五声音阶,柔和钢琴式音色,用于五子棋与大厅)。均为无缝循环。
  - 网页端用 HTMLAudio(浏览器要求首次点击后才允许自动播放),小游戏用 `wx.createInnerAudioContext` 播放同一批 `.wav`。

### 斗地主(`shared/doudizhu.js`)

## 第三期新增:炸金花(`shared/zhajinhua.js`、`shared/ai-zhajinhua.js`)

> **仅供娱乐,虚拟积分,不可兑换。** 只使用本机保存的「欢乐豆」,没有购买 / 充值 / 提现入口,界面(大厅、人机设置页、牌桌、状态栏)都显示该声明,UI 源码中不出现真钱相关字样(`tests/assets.test.js` 会检查)。

### 规则
- 2~6 人,每人 3 张牌,牌型大小:**豹子(三条)> 同花顺 > 金花(同花)> 顺子 > 对子 > 单张**。同牌型比点数(对子先比对子再比单张;金花 / 单张从大到小逐张比),**花色不分大小,完全相同算平局**。
- **A-2-3**:默认算顺子且是**最小的顺子**(小于 2-3-4);Q-K-A 是最大顺子;K-A-2 不算顺子。引擎选项 `a23:'off'` 可改为 A-2-3 不算顺子。A-2-3 同花是同花顺。
- **235 吃豹子**:可选规则 `special235`,**默认关闭**;开启后仅「不同花的 2-3-5」能吃豹子,其余情况它仍是最小的单张(同花 2-3-5 是金花,不吃豹子)。
- **底注**:每人先交底注 10(进池)。每局每人带入 1000 欢乐豆(虚拟),结算 = 期末 − 期初,**零和**。
- **单注与明 / 暗注**:`单注 unit` 初始 = 底注;**没看牌(暗注)**每次跟注付 `unit`,**看牌后(明注)**付 `2×unit`。
- **加注**:把单注提高到更高一档(档位 = 底注 × 1 / 2 / 5 / 10,即 10 / 20 / 50 / 100),加注者付新单注(明注付 2 倍)。**跟注**:付当前单注(明 / 暗如上)。**看牌**:随时可看(不占回合),自己才能看到自己的牌,别人只看到「已看牌」。**弃牌**:出局。
- **比牌**:必须**已看牌**,指定一名未出局的玩家,付**2 × 自己的跟注额**;大者留下、小者出局,**平局算发起者输**;比牌后双方互相看到对方的牌。第 2 轮起才能比牌(只剩两人时第 1 轮也可以)。
- **轮数与封顶**:一轮 = 所有未出局者各行动一次;超过 `maxRounds`(默认 10)轮**自动封顶开牌**;轮到的人欢乐豆不够跟注时也**直接开牌**(简化处理,没有边池)。开牌时所有未出局者亮牌,最大者赢底池,牌型完全相同则平分(余数给座位靠前者)。其余人都弃牌 / 落败时,最后一人直接赢,**不亮牌**。
- **虚拟积分**:`欢乐豆` 起始 2000,存本机;一局结算后若低于 **200** 自动补助到 **1000**(纯本地数值,不可购买)。**没有排行榜**(见下方审核风险)。

### 联机与人机
- **人机**:选 2~6 人桌(你 + 电脑)和难度(简单 / 普通 / 困难);**好友房**:6 位房间号,房主可设桌位人数 2~6(默认 4),空位**由电脑补位**,房主点「开始游戏」(坐满自动开局),真人超时 45 秒 / 点「托管」由电脑代打,断线 60 秒内可重连;一手结束后房主「再来一局」,庄家轮换。**快速匹配**:8 秒无真人自动转人机。
- **服务端校验**:轮次、操作类型、加注档位、是否买得起、是否已看牌 / 轮数是否允许比牌、目标是否有效,全部由 `shared/zhajinhua.js`(服务端与客户端共用同一份)判定;快照只发送自己看过的牌与比牌亮给自己的牌,开牌结算前不泄露任何人的牌。

### 电脑 AI(`shared/ai-zhajinhua.js`)
- 手牌强度 = 该牌在全部 22100 种三张牌中的百分位。三种风格:**tight(保守)**、**aggressive(激进)**、**bluff(诈唬 / 常暗牌施压)**,人机里按座位分配不同风格。
- **简单**:近乎随机;**普通**:强度阈值 + 底池赔率 + 风格;**困难**:对手「范围模型」(未看牌的对手视为任意牌;看牌后仍在局中 → 强度至少高于弃牌线;加过注 → 至少约 60 分位),计算对多人的胜率,与底池赔率比较后决定弃牌 / 跟注 / 加注 / 比牌(并选最容易赢的比牌对象),按风格适度诈唬、极强牌第一轮慢打。所有 AI 只使用己方视角,不偷看别人的牌。
- 实测强度(`node tests/zjh-bench.js 30000`,4 人桌 2 对 2、座位轮换、三种风格均分,每手每人带入 1000):

| 对局 | 测试档每手平均净得 | 95% 区间 |
|---|---|---|
| 困难 对 普通 | +8.2 豆 | ±1.8 |
| 困难 对 简单 | +19.1 豆 | ±2.3 |
| 普通 对 简单 | +24.3 豆 | ±4.0 |
| 困难 对 困难(自对弈) | −1.3 豆 | ±0.7 |

  解读:困难档对普通档有稳定但不大的优势;**没有和真人高手比过**,炸金花本身运气成分很大,不能说「必赢真人」。AI 不会读对手的下注习惯(跨手牌),也没有专门防「别人反复诈唬」的策略。

### 音效与音乐
新增音效(`tools/genaudio.js` 合成,原创):`chips`(下注 / 加注 / 跟注)、`fold`(弃牌)、`compare`(比牌)、`look`(看牌);发牌复用 `deal`,胜 / 负复用 `win` / `lose`。背景音乐复用 `music_lively`。均受界面上的「音效 / 背景音乐」开关控制。

### 微信审核风险(重要)
炸金花带有博彩玩法属性,微信对棋牌 / 类博彩小游戏审核**最严**:只能使用虚拟积分,**不得**提供购买 / 充值 / 兑换 / 提现 / 转赠,**不得**把积分与任何实物、虚拟物品、优惠挂钩,也不要做会让积分显得「有价值」的**积分排行榜**或炫耀 / 分享积分的功能(本项目故意没有排行榜)。即便如此,棋牌类目仍可能需要软著 / 版号 / 资质而被拒,请自行评估,必要时只在网页版或自有渠道使用。

| 象棋 | 第一期旧困难(深度 3) | 20 胜 0 负 | 100% |
| 象棋 | 旧普通档 | 20 胜 0 负 | 100% |

## 包体积
`wechat-minigame/` 实测合计约 **3.16 MiB(3,311,153 字节)**(三首背景音乐 + 24 个音效),低于小游戏主包约 4MB 的限制,但余量只有约 0.8MB;再加音乐或图片需要降采样率 / 缩短曲长,或把音频放到分包 / 远程加载。

## 已知不足 / 未验证
- **没有在真实微信开发者工具或真机上运行过**微信小游戏工程(包括 `wx.createWorker`);只做了结构检查、语法检查和 mock 驱动测试。`wx.*` 接口按文档编写,可能需要调整。
- **未实际收听音频**:只验证 WAV 合法、非静音、被正确触发;音色、音量需要人工试听。
- 斗地主 / 麻将的牌面、麻将牌是用 Canvas 画的简易图形,**没有在真实手机屏幕上看过**,只有 mock Canvas 的绘制不报错测试。
- 欢乐豆仅保存在本机,清缓存即重置;没有账号体系,没有排行榜。
- 象棋"长捉"是简化判定(捉无根子或高价值子且连续捉),与正式竞赛规则的细则有差异,不要当作裁判级实现。军棋未实现"司令阵亡后军旗明示"等变体;炸弹碰地雷按"同归于尽"。
- AI 强度只以对「第一期旧 AI / 普通档」的胜率衡量,**没有与外部强引擎或高手对比**,不能说"打赢真人高手";斗地主 / 麻将的 AI 基于启发式 + 采样,不是求解器。AI 在 CPU 较慢的手机上按时限搜索,实际强度会低于本机基准。
- 服务器是单进程内存存储,无持久化 / 无鉴权,不适合直接用于大规模公网运营;未做聊天、观战、微信登录。
- **炸金花**(第三期)的已知不足:没有边池(欢乐豆不够跟注直接开牌);同一手牌里的 AI 不记忆对手跨手的习惯;牌桌 UI 只用 mock Canvas 驱动测试过,**没有在真实屏幕 / 真机上看过**(6 人桌在小屏幕上可能拥挤);新增音效没有人工试听;联机里「比牌」只在 2 人桌的机器人测试中走过完整联机流程,多人桌比牌靠单元测试与本地人机界面测试覆盖;欢乐豆只存本机,联机时各人按自己的每局结算改本地数值,服务器不记账。

> 合规提醒:棋牌类小游戏在国内上架通常需要相应的软著 / 版号 / 资质与备案。本项目只提供技术实现,上架前请自行确认。
